# 兼容性与更新

当前包是开发版。版本要求、构建成功和真实浏览器验收是不同的证据，不能互相替代。

| 范围 | 当前证据 |
| --- | --- |
| DSH | 0.2.1-rc.5；Host 和扩展使用 wire v4，新增能力须双方协商 |
| Node / pnpm | 本轮使用 Node 24.22.1、pnpm 12.15.0；声明范围见根 package.json |
| Chrome | 本轮隔离环境使用 macOS x64 上的 Chrome for Testing 156.0.8078.4；不代表所有 Chrome 版本均已验收 |
| 常用 Chrome | 需另验扩展重载、工具栏授权和真实业务页面；隔离浏览器不能替代这项证据 |
| Firefox | 保留文本路径和独立构建；本轮没有做运行验收，不提供 Chrome 的截图、页面诊断或人工核对能力 |
| Desktop | 未实现共享任务集成 |
| 模型 | 脚本化测试与默认模型测试分别记录；合成项目通过不等于用户业务项目通过 |

安装包包含 Host tarball、Chrome ZIP、校验和及安装说明。运行 `pnpm run release:prepare` 生成本地开发包；不要用仓库根目录充当独立插件包。Host 插件与浏览器扩展须分别更新，目前没有浏览器商店自动更新渠道。

更新时保留原 DSH home 和 `web` profile。先等待任务及对话结束，再安装和重启 Host。Chrome ZIP 覆盖原扩展目录后，在 `chrome://extensions` 点击重新加载；保留固定目录和扩展安装身份才能复用原配对。更新后在扩展设置核对 DSH、Host、扩展和协议版本。自 0.1.35 起，也可在 DSH 设置的「浏览器配对」查看当前连接的扩展版本。旧扩展会显示「扩展已连接，版本未上报」。

对话、配对和任务资料应继续保留；旧页面须重新点击工具栏图标授权。排队任务和中断任务不会因更新自动执行。若保存结果不明，先只读检查实际业务记录，再用「核对未确认操作」逐项记录人工判断。核对不重发写入、不自动继续，也不证明任务完成。

连接失败时先检查扩展设置中的 Host 地址、版本提示及配对状态。对话能聊天不代表已授权页面；已连接也不代表有可操作的目标。不要通过删除 DSH home 修复连接。需要重新配对时，在设置中解绑与 DSH 的连接，再重新连接；停止控制某一页不会解绑 DSH。

`pnpm run test:smoke-release -- --dir <开发包目录>` 在临时 home 检查独立安装；`pnpm run test:smoke-upgrade -- --from <旧包目录> --to <新包目录>` 使用同一临时 home/profile 和固定扩展目录，检查历史、配对、任务资料、排队任务及授权状态。测试不会替换常用 Host。未知写入的核对与诊断另见 [Bridge 文档](../packages/browser/bridge-browser/README.zh.md#实时观察边界)及[扩展文档](../extensions/dsh-browser/README.zh.md)。

卸载 Host 插件不会自动清除对话和配对数据。回退前停止任务并备份原数据；新数据的降级兼容性没有保证，不能把回退当作自动恢复或业务撤销。

0.1.23 的显式表单状态属于有界快照文本增强，没有增加 wire v4 命令或参数。字段只描述 DOM 标志与数值属性声明，不能代替应用校验。旧扩展未输出这些信息时应保留未知；混用版本的局部测试不构成完整兼容承诺。

0.1.24 将扩展面板的目标显示限定到各自对话，内部分组选页继续检查会话归属、状态版本和页面地址；wire v4 命令不变。未绑定的历史对话仍需在面板中明确选页，已有未知操作仍需原生逐项核对。

0.1.25 补充扩展面板内部通道的会话/窗口登记恢复，保持 wire v4；恢复登记不会调用页面动作、恢复授权或自动运行排队任务。

0.1.26 的授权页列表增加当前调用会话的只读 `binding` 布尔字段，wire v4 不变。旧扩展没有这些字段时保留未知；字段不能替代原生选页或授权。授权范围为空时仍返回空列表，不附加绑定诊断。

0.1.27 在 `binding` 增加可选的 `lastSelection`，只描述本 Worker 观察到的原生选页请求。选页面板最多等待 12 秒；超时表示回执未确认，只刷新状态，不重放。后台原有 10 秒选页预算和 wire v4 不变。旧扩展缺少新字段时保留未知。

0.1.28 沿用 wire v4 和原核对清单结构：时间、类型与原因编码在已有 label 字段中，旧端仍可解析并显示文本；新面板遇到旧标签则回退显示。人工接管后的写入限制保存在扩展会话存储中；重新读取页面不能解除，须重新选择目标页。该选择也不能清除 Host 保存的未知操作记录。

Chrome 交互范围如下；“具备接口”不表示已完成所有真实站点验收。

| 交互 | 当前行为与边界 |
| --- | --- |
| DOM 点击、输入、选择、按键 | 在单页授权与当前观察范围内执行；只读字段及过期引用会拒绝；应用和服务端校验须另外核对 |
| 画布坐标 | 使用本次截图的单次引用和比例坐标，属于合成点击，不保证真实用户手势特性 |
| Console / Network | 用户在面板开启后读取有界错误类型、位置及请求状态；不返回消息全文、请求头、正文、原始路径或查询值；不能证明保存成功 |
| 上传、本地文件选择器 | 没有模型选择本机文件的工具；需要用户自行选择文件，再明确继续 |
| 下载、另存为 | 页面点击可能触发浏览器下载；没有选择本机保存位置、读取下载内容或核验文件完成的工具 |
| 浏览器权限、系统弹窗、原生菜单 | 不在网页 DOM 控制范围内，需要用户实际操作；不承诺自动确认 |
| 登录、验证码、账号与租户 | 用户完成登录；不要把凭据发到对话里。人工接管会停止旧写入，但静默身份变化仍需要可信站点集成校验 |
| 结果核验 | 可信 Host 可接入版本化后台读回；通用网页提示、HTTP 200 和人工解除限制均不替代业务结果证据 |

如果页面被接管后模型仍需读取资料，可继续只读；确认账号和结果后在「DSH 控制分组」重新选页。重载扩展会撤销旧页面授权，须重新点击工具栏图标；不要为了继续任务而删除对话或未知操作记录。核对清单的日期按本机时区显示，旧版本缺失日期时保留未知。

0.1.29 为诊断面板增加请求顺序与页面/对话/连接范围隔离，wire v4 和诊断权限不变。较早的轮询回执不能覆盖新开关状态；开关等待期间暂缓轮询，切换范围后旧请求失效。操作仍由用户实际点击，不会自动重试开启或停止。

0.1.29 同时保留后台临时重启或传输重连前的面板对话，只恢复视图登记和历史读取。明确断开/解绑或已知 Host 地址变化仍清理旧范围；恢复失败保留原对话并提示，不自动新建。此行为不恢复单页授权或续跑任务。

0.1.30 的诊断启用在 10 秒内未确认时失效，迟到原生回执不会继续启用或重放过期请求。原生清理尚未结束时，不让后续启用越过该页面的旧操作；清理后仍需实际点击重新开启。wire v4、只读诊断字段和权限保持兼容。该边界修复不证明已找到所有历史启用超时的原因。

0.1.31 的侧栏按当前对话接收页面目标和授权状态。切换对话或侧栏连接中断后，等待后台返回新状态。已授权页面仍可在会话登记后选择。安装时一起更新扩展的侧栏和后台，Host 继续使用 wire v4。

0.1.32 两端协商支持后，同一浏览器连接下的托管任务按标签页控制启动和继续。原任务仍在运行、停止中或有待核对的写入与恢复记录时，另一任务会收到侧栏提示并保持排队或暂停。不同标签页可以分别启动。这个检查的范围是当前连接内的托管任务，使用后台从浏览器取得的标签页编号。两端仍使用 wire v4，旧端沿用原有任务行为。

0.1.33 把托管任务的待确认写入关联到配对扩展当前会话中的标签页。扩展后台或 Host 重启后，同一浏览器会话重连时，其他任务仍须等待这次写入核对完成。旧操作记录保留原对话的核对限制。关闭浏览器或重载扩展后，使用新会话的标签页范围，页面需要重新授权。两端仍使用 wire v4。

0.1.34 给 Chrome 的页面结构读取和就绪检查加上等待上限。开页或导航已确认时，附带快照最多等 2.5 秒，超时后可单独读取快照。诊断开启超时后，扩展确认独占调试连接已断开时，侧栏可再次开启诊断。与页面控制或截图共享的连接继续按原顺序清理。两端仍使用 wire v4。

0.1.36 等 Chrome 确认新页加载完成后再连接调试器。就绪检查读取页面状态和主文档标识，控制脚本在需要读取或操作页面时才初始化。连接或初始化超时会撤回本次授权。Chrome 迟到的连接会在原标签页范围内清理，清理完成前同一标签页不能建立新的调试连接。两端仍使用 wire v4。

0.1.38 的侧栏手动选页要等浏览器写完会话存储，再确认原对话、页面和授权仍有效。发出请求的侧栏在等待期间显示「正在选择分组页面」，失败时显示「选页未确认」和原因。浏览器会话结束或重载扩展后，页面授权仍按原流程重新取得。
