# 浏览器扩展

[English](README.md) | 中文

Chrome/Firefox 扩展包含后台 Bridge 客户端、负责文本快照与页面动作的 content script，以及 React 侧栏。扩展需要配合本工作区的本机 Bridge，不能独立安装或启动 Host。

安装、一次性配对、安全边界和能力状态见[仓库首页](../../README.zh.md)。Chrome 和 Firefox 各自使用安装级凭据。Chrome 支持可见区域截图和绑定截图的合成坐标点击。原生 CDP 输入及网页文件传输仍未提供；Firefox 保留文本路径。

Firefox 构建目前使用独立于上游扩展的临时扩展 ID，尚未作为 Firefox 扩展正式发布。

线协议 v4 要求配套的 Host 构建。命令携带动作 ID、摘要和明确的旧式调用/运行范围。摘要检查通过后，先由扩展源 IndexedDB 事务提交执行占位。接纳并等到写入顺序后，扩展会向同一 Host 连接确认原始请求；复制运行 ID 或晚到的回复不能恢复权限，浏览器授权仍需单独满足。同一 ID 在占位保留期间只执行一次，worker 重启后仍有效；命令变化会被拒绝。存储只包含身份、时间戳及接纳/结束阶段，不缓存页面、输入原文或历史结果正文。最多保留 5,000 条占位，不自动过期或淘汰；存储不可用或已满时阻止新执行，损坏的已有占位会阻止对应动作。清除浏览器或扩展数据会移除这层保护。占位不代替用户授权、实时目标检查和业务结果验证，也不提供自动恢复或重放。

## 开发

在仓库根目录执行：

```sh
pnpm --filter dsh-browser-extension run build
pnpm --filter dsh-browser-extension run build:firefox
pnpm --filter dsh-browser-extension run typecheck
pnpm --filter dsh-browser-extension run test
```

Chrome 产物位于 `extensions/dsh-browser/dist/`，Firefox 产物位于 `extensions/dsh-browser/dist-firefox/`。仓库安装脚本会配置 `web` Host profile 并准备 Chrome 扩展。使用 Firefox 时，还需执行上面的 Firefox 构建命令，在 Firefox 打开 `about:debugging`，选择“此 Firefox”→“临时载入附加组件”，然后选择 `extensions/dsh-browser/dist-firefox/manifest.json`。这是临时安装，Firefox 重启后需要重新载入；详见 [Mozilla 临时安装说明](https://extensionworkshop.com/documentation/develop/temporary-installation-in-firefox/)。按仓库首页的步骤为 Firefox 扩展单独配对。

声明的网站权限仅有本机 DSH 通信所需的 `http://127.0.0.1/*`。Chrome 还声明了 `debugger` 和 `tabs`，其能力大于 `activeTab`，也能读取标签页信息；Stride 在插件代码中限制模型可见的页面和调试连接，不将它描述为浏览器强制的单页隔离。Firefox 保留 `activeTab`，不申请这两项 Chrome 权限。页面脚本仅在授权后加载。页面内容是不可信数据，修改动作仍按审批设置处理。DOM 点击、输入和选择需要最近一次观察给出的元素引用；坐标点击则需要绑定原会话与托管控制版本的新截图引用。两种引用均不识别账号或租户，工具派发仍需独立检查执行权限。

侧栏显示当前会话中由 Host 创建的浏览器运行，并提供暂停和停止按钮。停止请求会保持「停止中」，直到执行器确认。暂停任务的写入均已结束且无需恢复时，可先用会话上方的控件选择分组内已授权的页面，再点击「在已绑定页面继续」。这会使用选定的原生分组页面并增加运行的控制版本，不会恢复旧执行上下文；执行器须进入新上下文接手。DSH 网页的 `/browser <目标>` 命令可明确创建等待中的任务。到历史会话列表选择该会话和目标浏览器页面，再点击「绑定并开始」。这次真实用户操作会重新检查并绑定原生页面，之后 Host 才启动 Agent；读取历史或重新连接不会启动任务。首次模型回合之前，等待任务也会出现在会话列表。普通聊天不会自动创建任务，自动对账尚未实现。控制要求真实用户操作，携带所显示的记录版本，且不自动重试。Host 未提供可选的 `canRetarget` 能力时，不显示继续按钮。

任务累计上限为主动执行五分钟、十次模型请求接纳和二十次浏览器调用。已达到任一上限的任务不能启动或继续，侧栏保留「停止」按钮，并提示为剩余工作另建任务。暂停或更换页面不会重置计数，已经接纳的活动仍可完成独立核验。

Host 更新后，正常重启时只要侧栏开着，扩展就会使用现有配对自动重新连接。被其他客户端替换的连接仍需点击「保存并连接」。重连不会续跑中断的任务，也不会恢复旧页面绑定；Host 任务恢复尚未实现。

两端更新后，点击「停止控制此页」、关闭标签页或原生绑定失效，也会暂停对应任务并取消其 Agent。页面撤销通知确认后，DSH 仍保持连接，页面也会保留。请重新授权并绑定目标页，再明确点击「在已绑定页面继续」；仅授权不会续跑。已经开始的动作不能撤回，等待中或未决写入仍会阻止继续。Host 无法确认撤销通知时，worker 会关闭原连接，让 Host 按断连处理。旧的兼容组件保留通用暂停状态；页面失效后立即暂停需要协商启用 `taskTargetLoss` 能力。

在扩展设置中点击「解绑 DSH」，即可断开此浏览器与 DSH 的连接。它会清除本机凭据，重新打开侧栏或重启浏览器后也不会自动重连。Host 可访问时，还会撤销此浏览器的凭据并取消其待领取的配对请求；Host 未确认撤销时，界面会提示仅完成本机清除。网页和会话会保留，重新连接需要再次配对。

浏览器连接中断时，绑定到该连接的明确任务会暂停，并取消其中的 Agent 活动。重新连接不会续跑；请从历史会话选择原对话，确认页面的控制授权和绑定，再点击「在已绑定页面继续」。未决、失败或等待中的写入仍会阻止继续，Host 重启后的恢复尚未实现。若连接被其他客户端替换，可点击设置中的「保存并连接」，用原地址和凭据重新连接；保活和单独保存策略设置不会抢回连接。

「绑定并开始」或选页继续被拒绝时，只有 Host 明确确认尚未登记本次目标，扩展才会释放本次未使用的绑定记录。刷新任务状态后，用户可再次真实点击并建立新绑定。回执丢失或结果不明时保留原绑定，不自动重试。清理绑定记录会保留页面及其原生授权。

继续任务时会清除上一轮的结果提示，累计上限和已保存的证据保留。旧一轮核验晚到的结果不会让正在运行的任务显示「待核实，自动操作已停止」或「结果已独立核验」；本轮结果需要另行核验。

「已授权页面内免确认操作」在未保存过选择时默认开启。已保存的关闭或开启状态会保留，更新和后台重启不会改写。开启时，已授权页面内容自动分享，停用的分享下拉框会显示「自动」，并保留关闭开关后要恢复的原选择。关闭并保存后，会恢复该分享策略和通常的操作确认规则，包括已信任域名的例外。它不会授予页面访问权限，也不会绕过目标和撤销检查。

## 授权单个页面

使用已有页面时，打开目标页面，点击浏览器工具栏上的 DSH Stride 图标，再在侧栏选择任务和分组内的目标页面，并点击「绑定并开始」。从浏览器菜单打开侧栏、侧栏内点击按钮或发送模型指令都不会授权已有页面。同网站的其他标签页也需要单独授权。Chrome 新建页面可使用下文单独开启的自动控制流程。

已授权标签页会加入蓝色的「DSH 控制」分组，每个窗口各自管理。手动拖入未授权页面不会授予权限，插件会将它移出；拖出已授权页面或点击侧栏的「停止控制此页」会撤销 Stride 控制。Chrome 必须成功加入分组才能受控；固定标签页需先取消固定，分组失败时不授予控制权限。Firefox 保留原有按页授权路径，本次 Chrome 分组行为未在 Firefox 验收。尚未绑定任务时也可以停止控制。停止控制不会撤销已经派发的网页操作，也不会清除 DSH 配对。后台恢复时会重新核对标签页、网站和分组，旧缓存不能覆盖已保存的撤销记录。缓存不一致时，需要重新授权目标页面。浏览器的临时权限在导航或关闭时到期；停止按钮会立即撤销插件内的授权并停用页面脚本。

跨站跳转、关闭页面、重载扩展或重启浏览器后需要重新点击图标。Chrome 的临时授权可保留到同站点刷新后的页面；Firefox 在加载新文档后需要重新授权。扩展不会在重启后恢复页面授权，控制分组本身也不代表授权。跨域 iframe 的内容不在临时授权内，无法注入时仅处理可访问的主文档。参见 [Chrome activeTab 说明](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)和 [Firefox activeTab 说明](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/activeTab_permission)。

运行 `pnpm run test:smoke-page-access` 可使用临时 Chromium 配置和本地合成页面验收单页权限及分组；不会调用模型，也不使用日常浏览器配置。该检查需要支持 `Extensions.triggerAction` 的 Chrome for Testing。

Chrome 已移除助手跟随和切页交接确认。可在会话上方的「DSH 控制分组」中点击已授权页面；列表不包含未授权页面，选页也不会切换你正在看的标签页。新会话使用已有的分组目标，等待中的任务也按该选择启动，不会改用你正在浏览的分组外页面。运行中的任务不会随你的切页自动换目标；拖出分组仍会撤销控制并暂停对应任务。

分组已有授权页、但当前对话尚未选定目标时，面板会提示选择已有页面，无需重复授权。确认超时或没有面板接收确认时，Host 会拦住该 Agent 在本轮后续的浏览器请求。回到扩展后，发送新消息再试，并确认新弹出的请求；其他对话不受影响。

## 自定义下拉框与控制键

展开自定义下拉框后，重新调用 `browser_snapshot`，再用可见选项的 `elementRef` 调用 `browser_click`。快照收录 ARIA combobox/option 控件，以及已观察的 Element UI 下拉弹层和列表项结构。清单数量受限时，视口内的弹层选项排在弹窗和背景控件之前，并显示禁用、选中状态；不会把普通列表项推断成控件。隐藏、禁用、文字或所属弹层已变化的选项不能沿用可操作引用。`browser_select` 仍只支持原生 HTML select。这些 DOM 适配沿用原有页面授权、观察引用和操作确认，不读取框架内部状态。

`browser_press` 为常见控制键补充 `code`、`keyCode`、`which`，使旧版网页事件处理能够响应。事件仍是合成事件：Tab 不提供原生焦点移动，Enter 不提供原生表单提交。每次操作后须重新观察结果。

运行 `pnpm run test:smoke-widgets`，可用临时 Host 和隔离 Chrome 检查选项引用、禁用及关闭后拒绝、旧键盘处理，以及后台普通授权页和 DSH 新建页的实际 hash 路由渲染。加 `STRIDE_REAL_MODEL=1` 后，现有默认模型还须完成选择、仅保存一次、导航，并与独立服务端记录核对。私有模型输入沿用下文材料验收的设置，上限为二十次模型请求、三十次浏览器调用。证据位于 `.stride-private/validation/widgets/`。合成页面只复现已观察的 DOM 结构，不包含完整组件库或真实 CRM 后端；这些检查不代表所有 SPA 或 Desktop 均已验收。更新后须重建两端、重启 Host 并重载扩展，才能使用新指导和选项引用。

## 画布与设计稿

两端更新后，Chrome 可使用 `browser_screenshot` 和 `browser_click_at`。先授权设计页，再在「DSH 控制分组」中选定它。截图固定读取这个原生标签页，你在别处浏览也不会改变目标。截图遵循页面分享设置，坐标点击遵循操作确认和域名信任设置。图片包含整个可见区域及嵌入内容的像素，不套用文本快照的脱敏规则。

截图通过 DSH 图片附件服务保存，下一次模型请求可以看到图片；在 `run_code` 中调用也一样。工具文字不包含图片 base64 或本机路径。需要使用支持图片的模型，纯文本模型会收到 DSH 的图片能力提示。先看图，再给 `browser_click_at` 传入对应的 `screenshotRef`，以及**相对于整张图片的 x/y 比例**，范围均为大于等于 0、小于 1。例如图片宽度四分之一、竖直方向一半的位置为 `{ x: 0.25, y: 0.5 }`。Host 或模型缩放整张图片时，比例坐标仍保持一致。

处理设计画布时，可先点击截图位置选中图层，再用 `browser_snapshot` 读取属性面板里的数值。这依赖页面本来就有图层数据；上传的平面图片不会因此产生隐藏图层或精确 CSS。坐标点击向固定的主文档元素发送合成指针和鼠标事件，可用于 canvas 或 SVG；它不提供原生手势、拖拽、iframe 坐标操作、整页长截图或设计文件导出。

设计稿缩得太小、无法可靠定位图层时，可调用 `browser_set_design_zoom`，比例限 100–200%。它支持唯一且明确标注的原生缩放下拉框，以及已观察的蓝湖 `/web/#/item/project/detailDetach` 工具条菜单。蓝湖页面须置于前台；切到后台会阻止尚未执行的菜单选择。选择实际提供的 100%、150% 或 200% 等预设，不会把不支持的值自动取近似。适配器先进入精确的缩放入口，读取附近可见弹层的百分比选项，再重新检查原请求、页面授权和文档，才选择比例；不操作属性面板的不透明度或“放大/缩小”等非百分比项。读回工具条比例后须重新截图，不改 CSS 或浏览器缩放。准备期间拒绝该 Agent 的并行浏览器调用。配套扩展在未派发比例选择的预检失败中返回 `design-zoom-not-selected`，允许模型重新观察、换受支持的控件或请求缺失条件；不可把相同失败无依据地重复执行。比例选择或读回失败、传输结果不明时，仍停止本轮浏览器调用，新用户回合重置。普通页面文字不能解除限制；旧端未提供该信号时保留停止策略。展开后取消请求或撤销控制，会阻止尚未派发的选项操作；已展开菜单可能保留，已发生的效果不会被撤销。读取组件样式时，背景层和文字层要分别选择。先点背景留白，读取容器尺寸、填充色和圆角；再重新截图，选择文字，读取字体属性。两组数值分开整理，字重以属性面板明确给出的值为准，不根据图层名或字体名猜测。切换设计稿后，重新截图，并核对新稿中选中的图层，再报告属性。

截图引用只能使用一次，只存在内存中，并绑定原会话、文档、页面授权、连接和托管控制版本。同一页面再次截图会替换之前的引用，即使来自另一个对话。滚动、窗口尺寸或缩放变化、观察到的 DOM 改动及页面输入都会让它失效。动画画布可能在没有 DOM 事件的情况下重绘，因此操作前应重新截图，并核对点击后的属性面板。点击回执不能单独证明图层选对或业务操作完成。

坐标超出图片范围、引用已使用、属于其他对话或原授权失效时，会在弹出操作确认前直接拒绝。拒绝一个有效的点击请求不会消耗截图引用。确认之后仍会再次检查引用归属和页面视口；等待确认期间重新截图或页面发生变化，仍可能使点击失效。

Chrome 可能显示调试提示。视觉连接保留在已授权的分组页上，使截图与点击的视口保持一致；手动页面授权不会因此变成跨站控制。停止控制、取消浏览器调试、目标归属失效或 DSH 断线会撤销连接。worker 重启会清理记录的视觉连接，不恢复截图引用。其他调试器或浏览器策略可能阻止截图。可选的 `visualViewport` 能力保持 wire-v4 文本端兼容，需要一起构建并重启 Host、重载扩展。

运行 `node scripts/smoke-visual.mjs`，可用临时 Host、Chromium 和合成画布验收，不调用模型。检查包括真实图片附件存储、在另一标签页可见时核对受控页像素、背景层和文字层分别回读、引用单次使用和会话隔离、滚动及缩放失效、同页切稿后旧坐标拒绝及新图像和属性核对、原生撤销控制和 worker 重启后的连接清理。设置 `STRIDE_REAL_MODEL=1` 可追加现有默认模型的分层选择和精确数值检查，沿用下文可选的私有输入 `STRIDE_MODEL_PATCH` 和 `STRIDE_MODEL_CREDENTIALS`；该会话最多十次模型请求、二十次浏览器调用。仅使用合成页面，`.stride-private/validation/visual/` 中保留元数据，不保存真实设计稿内容；这不代表 Firefox、Desktop 或真实网站已经验收。

自动放大验收：`STRIDE_REAL_MODEL=1 STRIDE_AUTO_ZOOM=1` 验证原生下拉框；再加 `STRIDE_LANHU_ZOOM_MENU=1` 使用本地合成的蓝湖菜单，独立映射测试域名，不登录真实蓝湖。此模式先暂停菜单准备结果并停止页面控制，确认不会派发选项操作，再重新授权进入模型验收。模型必须实际调整比例、报告与独立检查一致的值、重新截图并准确读取两层属性；另加 `STRIDE_AUTO_ZOOM_FALLBACK=1` 可验证没有可用控件时请求人工处理；单独加 `STRIDE_AUTO_ZOOM_RECOVERY=1` 可验证专用缩放预检失败后，重新观察并用已识别的原生控件完成缩放、截图和分层读取。上限为十四次模型请求、二十次浏览器调用；私有结果文件为 `auto-zoom.json`、`auto-zoom-fallback.json`、`auto-zoom-recovery.json`、`lanhu-zoom.json`、`lanhu-zoom-fallback.json`。两端仍使用可选 wire-v4 `designViewZoom`，中间步骤只在扩展内部传递。更新后重建、重启 Host 并重载扩展。2026-11-04 已另外在常用 Chrome 的 DSH 新建受控验收页中，用现有默认模型将真实蓝湖工具条从 27% 调至 150%，并通过工具文字和独立页面读取核对比例，原页面保持不变。本次真实检查只确认比例操作和读回；合成页面的截图与图层读取检查不能代替真实稿件的画布渲染或整页还原度核验。

运行 `STRIDE_REAL_MODEL=1 pnpm run test:smoke-materials`，默认分别用全新的临时 Host 和独立 Chrome 验证六种任务：纯需求正文、正文内嵌设计图、Wiki 页面本身作为实现目标、材料冲突、用户明确指定优先来源，以及提供临时项目的只读任务。各项开放相同的浏览器工具；模型须结合任务判断用途。纯需求核对业务事实；混合材料须从实际截图读出仅存在于设计图中的编号和视觉标注；页面目标须调用布局工具，并与独立 DOM 量测一致。冲突须保留两个来源的值；用户没有指定优先级时请求确认，指定后按其要求处理。只读项目用例额外开放限定文件的 read/write/edit 工具，要求成功读取项目，并核对没有尝试修改、文件字节保持不变。仅纯需求样本检查未调用设计工具，不把它作为所有 Wiki 的禁令。回答按各任务的完整 JSON 结构核对，拒绝额外或缺失字段，允许对象字段顺序不同。可用 `STRIDE_MATERIAL_CASE=requirements|embedded-design|page-target|conflicting-materials|resolved-materials|read-only-project` 单独复核一项。私有结果位于 `.stride-private/validation/materials/`；单项文件与全量汇总 `result.json` 分别记录实际运行范围。临时项目的只读检查不代表已经完成用户项目的代码修改或真实联调。

Host 新增的 `browser_read_design_styles` 可把当前可读的属性标签整理成固定字段，并保留原文依据、缺项和冲突。它复用现有页面读取权限；不支持的面板布局仍用快照读取，背景与文字分别处理。已通过默认模型加合成页面的分层读取检查，并在放大视图后验证了常用 Chrome 的所测蓝湖面板；其他布局需另验。更新后重启 Host 并重载扩展，文本读取才能保留属性换行。参数、支持格式与限制见 [Bridge 样式字段说明](../../packages/browser/bridge-browser/README.zh.md#读取设计稿样式字段)。

对于生成的 DOM 页面，`browser_measure_layout` 能直接读取元素间的实际距离和计算后的 CSS 间距，不改动页面。选择器缺失或不唯一会报错，无法形成明确对齐间距时保留 `null`。它沿用页面授权和读取分享审批，需要两端更新；不测量画布图层，也不证明整体还原度。详见[布局测量](../../packages/browser/bridge-browser/README.zh.md#测量页面实际布局)。

## 自动控制 Chrome 新页面

在设置中开启「自动控制 DSH 新建页面」并保存，默认关闭。之后普通 DSH 对话通过 `browser_open_tab` 创建页面时，扩展会对本次实际创建的标签页授权、加入控制分组并绑定原会话，无需再点击工具栏图标。后台打开时保持原页面在前台。此设置允许新建页面，读取内容和后续操作仍遵循页面分享与确认设置。原有标签页和手动拖入分组的页面不会获得权限。

Chrome 控制器在独立的脚本环境中运行扩展自带的页面操作代码，目前仅支持 HTTP(S) 主文档。该新标签页跨站导航后仍可控制；子框架和选中文字引用暂不支持。关闭页面、移到其他窗口、拖出分组、点击「停止控制此页」、关闭设置、解绑 DSH 或取消浏览器调试连接都会撤销控制。已派发的操作无法撤回。后台或浏览器重启、重载扩展后不会恢复自动页面授权；可让 DSH 新建页面，或改用工具栏授权。Chrome 可能显示调试提示；其他调试连接或浏览器策略也可能阻止连接。

准备控制器不代表写入已派发。真正发送操作前，会再次检查原请求、目标和截止时间；脚本执行使用浏览器提供的唯一上下文标识，避免跨进程后复用数字编号而选错文档。恢复手动页面授权时也会检查原生脚本访问能力：Chrome 能提供标签页链接，并不代表扩展仍可访问页面。

新页面绑定失败时，会先撤销本次创建所持有的页面授权，再尝试关闭标签页。浏览器拒绝关闭时，页面保留但不再受控，并提示关闭结果未确认。用户停止控制或通过工具栏重新授权后，旧请求也不能再撤销新授权或关闭该页面。

Firefox 暂不提供此模式。Chrome 已保存自动控制设置时，排队的 `/browser` 任务可在卡片中输入完整 HTTP(S) 网址，点击「新建页面并开始」。Host 在创建标签页前先预留本次启动，扩展创建、授权、分组并绑定新页后才启动 Agent。确认尚未启动的失败只清理本次页面，用户已接管时保留；启动回执不明时保留页面和绑定，不自动重试。任务中的模型仍不能新建、跟随或关闭标签页。旧 Host 不显示这个可选入口，保留选页启动。`pnpm run test:smoke-browser` 使用真实 Host 工具调用验收自动控制本地合成页面，不调用模型，也不能作为 DSH Desktop 集成的验收证据。真实模型的新页任务验收见 [Bridge 说明](../../packages/browser/bridge-browser/README.zh.md#明确发起网页任务)。

Host 的模型提示会引导页面任务使用浏览器工具，说明如何从 `run_code` 返回观察结果，并要求在看到用户所需的页面确认后结束。页面提示与独立核验的持久化结果会分开表述，避免转用命令行、直接网络请求或反复保存。这些提示不会授予权限，也不保证模型执行稳定；普通对话仍不会创建受管理的任务。

### 普通对话的真实模型验收

构建后，设置 `STRIDE_REAL_MODEL=1`，运行 `pnpm run test:smoke-auto-tab-model`。可用 `STRIDE_MODEL_PATCH` 指定私有 DSH 配置补丁，用 `STRIDE_MODEL_CREDENTIALS` 指定已有凭据文件。脚本使用临时 Host 配置中的默认模型，不另选模型；需要沿用日常默认配置时，通过私有补丁传入。凭据副本仅放在临时 home，结束后删除；这两个输入文件都应放在 Git 之外。

验收会创建临时 Host、Chromium 配置和合成站点，通过扩展界面启用自动控制，再从扩展历史工作区以外的普通 DSH 会话提交“打开网页、修改开关、保存”的请求。目标页面不预先点击工具栏授权，也不预先绑定。完成条件包括模型回合结束、新页绑定原会话、仅新页获得授权并加入原窗口的蓝色「DSH 控制」分组、调试连接可用、页面显示保存成功，以及服务端独立状态确认已保存。测试会将该会话限制为最多十二次模型请求、二十次合成页面浏览器调用，仅将验收元数据保存到被忽略的 `.stride-private/validation/auto-tab-model/`。元数据包含输出长度，以及浏览器和 `run_code` 结果是否出现合成页面的保存提示，不保留正文。该结果只覆盖这一项 Chrome 合成场景；Desktop、Firefox 和其他网站需分别验收。

该验收会话的测试守卫会拒绝非浏览器工具；即使页面已保存，只要出现这类调用，整轮也判为失败。应将其记录为模型选工具失败，不能用重跑成功代替稳定性验收。

## 等待中的页面调用

收到操作页面的工具请求时，后台会在等待 IndexedDB 执行占位、审批或写入顺序之前固定已选标签页、窗口和 URL。浏览器导航与历史事件会使旧文档代次失效，包括相同 URL 的重新加载；重新绑定、标签页替换或移动、连接更换也会使旧绑定失效。被拒绝的调用不会自行改到新页面重试，已过期的读取结果不会返回。已经派发的操作仍须先结束，后续写入才能开始；它们不会被撤销或重放。已派发的动作可以在原绑定仍有效时观察自己引起的导航。

会话恢复检查点会重新固定文档与绑定代次，并在浏览器返回标签页读取结果后再次检查。即使标签页 ID 相同，晚到的读取也不能覆盖新的检查点。延迟完成的跟随或新建标签回调，在修改绑定或会话提示前也会检查原连接是否仍有效。

单次请求的文档检查存在于 worker 内；Host 与 worker 也会保存运行/控制版本的标签页绑定，首次有效的托管页面调用通过确认建立它。后续调用不会跟随重新绑定、标签页替换/移动/ID 复用或新连接，即使 URL 相同也不例外。「在已绑定页面继续」会在执行前为新版本登记新的绑定；首次执行确认成功之前，所选文档须保持有效。之后仍支持同标签页导航，等待中的旧文档请求仍会失效。托管运行仍不支持新建/跟随/关闭标签工具；暂停任务可通过明确的页面绑定和继续按钮交接。普通未托管会话也只能跟随或关闭已授权标签页；未开启 Chrome 自动控制时，模型新建的标签页会保留打开，但不会自动绑定或获得页面访问权。账号/租户识别及自动对账仍未实现。
